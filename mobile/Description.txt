1️⃣ What you are doing now: Stream Copy

Your current trimVideoMinimal just copies a portion of the video without re-encoding.

Pros:
Very fast, almost instant.
No quality loss.

Cons:

Cannot modify the video. You cannot:
Add text overlay
Add image overlay
Do green screen/chroma key
Adjust colors, crop, rotate, etc.
Why: Filters like drawtext, overlay, chromakey require decoding the frames and re-encoding them. Stream copy just slices the video file as-is.
2️⃣ What you need for overlays or green screen: Decode → Filter → Encode
You must decode the video frames into memory, apply filters, then re-encode into a new file.
This uses FFmpeg libavfilter (buffersrc, buffersink, drawtext, overlay, chromakey).
Example possibilities:
Add text: drawtext=text='Hello':x=100:y=50:fontfile=/path/to/font.ttf:fontsize=24:fontcolor=white
Add image overlay: overlay=x=50:y=50
Green screen: chromakey=color=0x00FF00:similarity=0.1:blend=0.0
3️⃣ Implication

Your current method cannot do this.

To see green screen or add overlays, you need a full re-encoding pipeline, which is:

Open input file.

Decode video frames.

Apply filters (drawtext, overlay, chromakey…).

Encode frames to output.

This is slower than stream copy because it re-encodes the video.

=====
Input video
↓ decode
↓ chromakey / drawtext / overlay
↓ encode
↓ output.mp4
↓ <Video source={{ uri: output.mp4 }} />

=========
Input video
  ↓
FFmpeg decodes internally
  ↓
libavfilter:
  - chromakey
  - drawtext
  - overlay (image/video)
  ↓
libx264 encoder
  ↓
output.mp4
  ↓
React Native <Video />
